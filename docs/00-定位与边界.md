# 定位与边界

> 本文件说明本项目**是什么、以及明确不做什么**。
> 主动划清边界，比罗列功能更能说明工程判断。

---

## 一、定位

**一句话**：在 ARM 边缘设备上实现 IEC 60870-5-104 子站，南向以 Modbus RTU 接入真实设备，
北向提供四遥与遥控选择-执行闭环，并与第三方独立实现的主站完成互操作验收。

**问题类型**：**执行侧**——把数字安全地变回真实动作。
核心难点是**动作不能出错**：状态不乱、时机正确、失败可检出。

**主体是什么**（这一句防止项目退化）：

> 主体是**遥控闭环 + 与第三方主站互操作**。
> 写子站是**载体**；四遥对象模型、遥控安全语义、互操作验收才是要证明的能力。
> 若丢掉这句话，本项目会退化成"造一个从站的练习"。

---

## 二、必须主动声明的话

> **本系统假定安全由外部硬件回路负责。软件只做判断，不承担功能安全。**
>
> **实时控制与联锁由 PLC 负责；本系统负责秒级/调度级的判断与执行。**

说出这两句，比做出功能更能体现专业度。

---

## 三、术语纪律

| 用 | 不用 | 原因 |
|---|---|---|
| 条件联锁 / 动作约束 | ~~安全联锁~~ | 后者是认证硬件的词 |
| 失效时的默认状态设计 | ~~fail-safe~~ | 后者暗示安全等级 |
| 秒级 / 调度级 | ~~实时~~ | 本协议的超时参数本身就在秒级 |
| 互操作性经验证 | ~~已对接真实系统~~ | 对端不是生产系统 |

---

## 四、做什么 / 不做什么

### 做

| 范围 | 内容 |
|---|---|
| 南向 | Modbus RTU 采集真实设备；点表映射 |
| 对象模型 | 信息对象地址编址、品质描述、毫秒时标 |
| 北向 | IEC 60870-5-104 子站：链路建立、总召唤、遥测遥信上送 |
| 控制 | 遥控「选择-执行」两段式、超时、越限拒绝 |
| 质量 | 设备掉线 → 品质位无效，而不是上送旧值 |
| 运行 | systemd 原生部署、看门狗、掉电恢复 |
| 互操作 | 与第三方独立实现的主站联调并留证 |

### 不做

| 不做 | 为什么 |
|---|---|
| 功能安全（急停 / 人身安全 / 消防） | 认证硬件的职责（ISO 13849 / IEC 61508 / IEC 62061） |
| IEC 61850（MMS / SCL） | 工程量与本周期不匹配 |
| 驱动 / 内核裁剪 / BSP / Yocto / Buildroot | 属另一个职业方向 |
| PCB 设计 | 同上 |
| 视觉 AI | 与命题无关 |
| 自建 SCADA 画面 | 主站侧使用现成工具，时间留给子站 |
| 多连接 / 集群 / 云平台 | 先把一条链路与一台主站做扎实 |
| 毫秒级实时控制 | 属 PLC 职责 |

## 五、许可证纪律

| 依赖 | 许可 | 处置 |
|---|---|---|
| 主流开源 104 实现 | **GPL-3.0** | 可读其源码学结构、可作对端跑互操作；**代码不得并入本仓库** |
| 本项目自身开源许可 | **待定**（仓库暂无 LICENSE） | 项目成形后再定；避免过早承诺，也避免"文档里写了、仓库里没有"的不一致 |

原则：**只借鉴架构，不复制代码。**

## 六、诚实边界

| 项 | 真实 / 说明 |
|---|---|
| RS485 现场设备 | 真实（模拟量变送器 + 继电器模块） |
| 遥控动作 | 真实（继电器吸合，且触点可回读） |
| 与主站的互操作 | 真实（第三方独立实现） |
| 主站本身 | 由现成工具扮演，**不是真实调度系统** |
| 被控对象 | 桌面继电器与指示灯，**不是一次设备** |
| 性能与规模 | 单连接、数十个点，**不做外推** |
| 协议覆盖 | **ASDU 子集**，实现清单需如实维护 |
| 物理层取证 | 逻辑分析仪只提供数字时序，**看不到振铃/反射/共模** |

> 尚未验证的能力一律标注"未验证"，不写成"已实现"。
