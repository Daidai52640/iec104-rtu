## 三、造什么（范围）

### 3.1 第一件事：整理一张参数表

动手前，把用到的**类型标识、传送原因、品质位、超时参数**整理成一张表，逐条标注标准出处。
**不许凭记忆写**。至少覆盖（常见取值，**首次实现前必须与标准原文逐条核对**）：

| 用途 | 名称 | 常见类型标识 |
|---|---|---|
| 单点遥信 | `M_SP_NA_1` | 1 |
| 带时标单点（变位/SOE） | `M_SP_TB_1` | 30 |
| 短浮点遥测 | `M_ME_NC_1` | 13 |
| 单点命令（遥控） | `C_SC_NA_1` | 45 |
| 短浮点设定值（遥调） | `C_SE_NC_1` | 50 |
| 总召唤 | `C_IC_NA_1` | 100 |
| 对时 | `C_CS_NA_1` | 103 |

同时建一张会话参数表：`k` / `w` / `t0` / `t1` / `t2` / `t3` / 序号范围。
⚠️ **APCI 里没有 CRC 字段**（CRC 是串口规约的事，别把别处的习惯带进来）。

### 3.2 四遥必须各有着落，不许含糊

| 遥 | 靶子 | 要求 |
|---|---|---|
| 遥测 | 真实变送器 | 数值与独立来源对得上 |
| 遥信 | 继电器反馈触点 + 一个外部按钮 | 变位带时标上送 |
| 遥控 | 继电器输出 | 「选择 → 执行」两段式，超时拒绝 |
| 遥调 | ⚠️ **必须有可写靶子** | 见下 |

> ⚠️ **遥调没有靶子就不要写"四遥全部闭环"。**
> 变送器只读，写不进去。两条路选一条，**不许含糊**：
> ① 用子站自身可写参数当靶子（例如把报警阈值做成可写项，主站改阈值 → 手捂传感器越过新阈值 → 遥信变位）；
> ② 明确降级为"仅做 ASDU 类型与单测覆盖，无现场靶子"，并写进边界。

### 3.3 回读必须走独立路径（否则是假确认）

当前计划的 `DO1 COM/NO → DI1` 在**同一块模块**上：
模块失电或损坏时，**命令路径与回读路径同时失效**，会给出"回读成功"的假象。

**必须**加一条与命令路径无共模的独立通道（第二块模块 / 独立输入通道 / 电流或光敏检测），
并在文档里写清这条共模边界。**做不到就如实声明"回读存在共模，不能作为唯一依据"。**

### 3.4 对端与取证

| 项 | 要求 |
|---|---|
| ⭐ **对端不少于两个不同实现家族** | 只用一个对端 + 参照它的结构写自己的实现 = 自证 |
| ⭐ **加一个独立解码器交叉核对** | 用抓包工具的规约解析功能逐字段比对（**具体工具与版本需实测确认**） |
| **对端取证规格** | 名称 + 版本 + 提交号 + 配置文件 + 连接日志。**不许写"某开源工具"** |
| **许可证** | 逐条写明；把开源实现当**独立进程对端**使用，不把代码并入本仓库 |

### 3.5 时间基准

⚠️ 老款 ARM 板**没有 RTC**，重启后时间会跳变，会污染毫秒时标与变位顺序记录。

必须做：NTP 同步 + 单调时钟测量耗时 + **"无 RTC 时时间跳变"的边界声明**。

### 3.6 负面用例（比成功路径更有说服力）

做成一张表，每条都要有实测现象：

- 超时之后才到达的「执行」怎么处理
- 选择/执行位写反
- 越限设定值
- 被拒绝后确认不动作
- 输出通道粘连（命令发出但触点不动）
- 序号回绕
- 拔网线 / 链路断开 / 重连

### 3.7 网络层实验（两台机器的价值全在这里）

必须留证：拔网线、链路断开、`t3` 超时、重连握手。
不做这些，多一台机器就是白花。

### 3.8 可复现模式

提供**无硬件仿真模式**（模拟 RTU 从站 + 模拟输出通道），使陌生人只拿仓库就能跑完整链路。
真机证据与仿真证据**分开标注**。

## 四、不造什么（砍单）

| 砍掉 | 理由 |
|---|---|
| 物理层波形章节、逻辑分析仪取证、MAX485 采购 | 本协议跑在 TCP 上，物理层不是必需；资源留给会话与遥控 |
| 顶层交互式 HTML 的**继续投入** | 已有一份够用；代码跑起来之前不新增视觉资产，首屏一律用 PNG |
| 第二台机器专门装系统 | 先用现有机器或虚拟机桥接跑真实 TCP；专用机器可选 |
| 第二条总线 / 不同芯片的转接器 | 除非第一个模块确实改不了串口参数 |
| 看门狗 / 多机部署 / "ARM 迁移"这类叙事 | `systemd` unit 保留（服务本来就要跑），但它是**手段不是证据** |
| 序号回绕的专门演示 | 一行取模实现即可，不必花时间做证据 |
| 台账密度（大量 ADR / 边界清单 / 验收脚本） | 按需写，不追求数量 |

## 五、证据规格

### 5.1 首屏证据链（一张图说清一件事）

⚠️ **动作影像只证明"会动"，不证明"这是本协议的子站"。**
首屏必须是**同一动作、同一时刻**的三件套同框：

1. 对端界面/日志（显示遥信状态或命令结果）
2. 抓包工具的逐字段解析（能看到信息对象地址与选择/执行位）
3. 实物照片（继电器实际吸合、指示灯亮）

### 5.2 每个交付阶段的验收都要加一列"可拍摄物"

拍不出来的一步，就等于没做完。

### 5.3 文档纪律

- 每条结论带**证据字段**（实测数字 / 复跑命令 / 未验证标记）
- 文档**可以薄**，但**证据等级要提高**：优先放原始抓包、原始日志、原始波形，少放转述
- 未验证的一律写"未验证"

## 六、命名与结构

| 项 | 要求 |
|---|---|
| 模块命名 | 用本行业的词：`link/`（链路层）、`asdu/`（应用规约）、`station/`（对象模型）、`io/`（现场 I/O）、`control/`（遥控） |
| ⭐ 闭环独立成模块 | `control/` 必须独立存在（控制状态机、超时、越界拒绝、回读确认），不要塞进主循环 |
| 状态机显式化 | 会话状态机与遥控状态机各一个模块，各配一张状态转移图 |
| 时钟可注入 | 会话与遥控逻辑必须能在**无网络、无硬件、假时钟**下单测。做不到就等于没有纵深 |
| 目录 | 必须有一个专门放**互操作验收证据**的目录 |

## 七、6 周排期（每周 10~15 小时）

| 周 | 必做 | 通过标准 |
|---|---|---|
| **W1** | 下单硬件；变送器在开发机读通；**抓一次对端与它自带仿真的真实会话并用抓包工具逐字段解码**；据此写编解码 + 逐字节对拍单测 | 能用真实抓包解释每个字段 |
| **W1** | ⚠️ **拍板主站工具**（见下） | 有明确选择与理由 |
| **W2** | TCP 服务 + 链路建立 + 测试帧 + 总召唤，上送 2 个遥测点 | 独立对端连上并总召唤成功（截图 + 抓包） |
| **W3** | 遥控选择/执行 + 超时拒绝 + 真实继电器动作 + **独立回读** | 命令→动作→回读→变位上送全链闭环 |
| **W4** | 品质位、带时标变位、NTP、假时钟单测、两张状态转移图 | 掉线时该点标为无效而非上送旧值 |
| **W5** | 负面用例表、网络层实验、ASDU 子集清单、点表对账、现场排障页 | 每条负例有实测现象 |
| **W6** | `systemd` unit + 安装脚本；首屏证据链；互操作证据目录 | 陌生人按文档能跑起来 |

**该做（有富余再上）**：遥调靶子；第二个不同家族的对端；无硬件仿真模式；物理层波形。
**可砍**：见第四节。

### ⚠️ W1 必须拍板的一件事

**最省事的带图形界面的主站工具多为 Windows GUI**，而本项目立过"运行链路不含 Windows"的原则
（见 `01-拓扑与设备归属.md`）。二选一，**不许拖到 W3 才发现**：

- ① 主站用 Linux 命令行工具（只有终端日志，首屏证据靠抓包补足）
- ② 放宽原则，明确声明"主站工具运行在 Windows，**仅作为对端**，不属于被交付的链路"

**具体工具的可得性、许可证、是否还在维护，必须实测确认后再选。** 我不替任何具体工具背书。
