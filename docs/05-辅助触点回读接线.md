# 辅助触点回读接线

> 目的：把验收第 3 条「触点回读确认」做实——**读继电器自己的触点**，而不是读 PLC 的 Y 映像。

---

## 0. 为什么必须接

现在回读的点是 IOA 5，读的是 **`0x0500`（PLC 的 Y 输出映像）**：

```
写 Y0 ──► PLC 的 Y 映像变成 1 ──► 读回来也是 1
           ↑ 写入和回读走的是同一条路径
```

⭐ **模块一坏，两边一起错**，回读就变成了"确认自己"而不是"确认现场"。

接上辅助触点之后：

```
写 Y0 ──► 继电器线圈吸合 ──► 触点闭合 ──► X0 读到 1（外部电平）
                                          ↑ 这才是独立的证据
```

---

## 1. 接线总览

| 从 | 到 |
|---|---|
| 继电器 1 的 **NO（常开）** | 板子的 **X0** |
| 继电器 1 的 **COM（公共）** | X 输入的**公共端（S/S 或 COM）** |

⭐ 用 **NO 不用 NC**：NO 是"吸合才通"，正好对应"输出为 1"。

另一组（继电器 2）同理接到 **X1**。

---

## 2. ⚠️ 先摸清 X 输入的极性，别急着接

三菱 FX 的输入分**漏型 / 源型**，接反了读不到：

```
漏型（sink，最常见）：S/S 接 24V+ ，X 端子通过开关接 0V
源型（source）    ：S/S 接 0V  ，X 端子通过开关接 24V+
```

### 摸极性的安全办法（不拆线、不改程序）

**① 连上 GX Works2**

```
连接目标：串行 RS-232C  /  COM3（板载 USB 那个口）
速度：115.2 Kbps    校验：7-E-1    机型：FX3U(C)
```

**② 进 `诊断 → 设备监视`，监视输入 `X0`**

现在应该是 `0`。

**③ 拿一根导线，点一下 X0 和 24V+（碰一下就松）**

| 现象 | 结论 |
|---|---|
| X0 变 `1` | **漏型**：S/S 接 24V+，触点要接 **0V 侧** |
| X0 不变 | 换着点 X0 和 **0V**，能看到 1 就是**源型** |

⚠️ **只用手点线，绝对不要把 24V 和 0V 直接短在一起。**

---

## 3. 正式接线

```
⚠️ 先断电（24V 断开）
```

按上一步测出的极性接：

```
继电器1 COM ──┐
              ├── 接到 X 输入的公共端（S/S 或 COM）
继电器1 NO  ──┴── 接到 X0
```

接线完成后：**上电 → 板子 RUN**。

---

## 4. 验证（接完立刻能验）

**① 用 GX Works2 强制输出**

```
在线 → 调试 → 强制输入输出  →  强制 Y0 = ON
```

| 检查 | 期望 |
|---|---|
| 继电器 | 听到"嗒"一声吸合 |
| 监视 X0 | 变成 `1` |

**② 强制 Y0 = OFF**

| 检查 | 期望 |
|---|---|
| 继电器 | "啪"一声松开 |
| 监视 X0 | 回到 `0` |

⭐ 两条都对上，物理闭环就成立了。

---

## 5. 接线后要改的一处配置

点表里已经**预留了独立回读的点**，接线后只要把命令的 `readback_ioa` 从 `5` 改成 `7`：

`config/points-rtu.json`：

```jsonc
{"ioa": 7, "unit": 2, "kind": "bit", "address": 1024, "bit": 0}   // X0 = 1024 = 0x0400
```

```jsonc
{"ioa": 10, "type": "C_SC_NA_1", "name": "DO1", "value": false,
 "actuator": 0, "readback_ioa": 7}      // ← 5 改成 7
```

| IOA | 含义 | 来源 |
|---|---|---|
| 5 | `DO1_image` | Y 映像 `0x0500`（PLC 自己认为的状态） |
| 6 | `DO2_image` | Y 映像 `0x0501` |
| **7** | **`DO1_contact`** | **X0 `0x0400` bit0（真实触点）** |
| 8 | `DO2_contact` | X1 `0x0400` bit1 |

⭐ 两个点并存是**故意**的：主站能同时看到"我以为"和"实际"，一眼看出差在哪。

---

## 6. 接线后能证明什么

| 场景 | 改之前 | 改之后 |
|---|---|---|
| 继电器正常动作 | 回读 = 1（其实只是 Y 映像） | 回读 = 1（**触点真的闭合了**） |
| 继电器线圈坏了 | ⚠️ 回读**仍然** = 1（假成功） | ✅ 回读 = 0 → 命令被否定确认 |
| 触点机械卡死 | ⚠️ 察觉不到 | ✅ 检出 |

⭐ 第二行是这一整套做法的全部意义：**"输出写了但没动作"是最危险的故障**，
因为它看起来一切正常。

---

## 7. ⚠️ 硬件参数速查

| 项 | 值 |
|---|---|
| X 输入区 | `0x0400`（1024），**FC04 读输入寄存器**，一个字装多个开关量 |
| Y 输出区 | `0x0500`（1280），**FC01 读 / FC05 写线圈** |
| 485 | `485A0 / 485B0`，4800 / 8N1 / 地址 2 |
| 编程口 | 115.2 Kbps / 7-E-1，机型 FX3U(C) |
