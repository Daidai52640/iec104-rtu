# 全链路拓扑：设备、电脑、接线、归属

> 用途：动手前把"什么设备接哪台电脑、用什么线、什么参数"一次定清楚。
> 本文只描述拓扑与归属，不写代码。
> 最后更新：待设备到货后回填（继电器模块参数、Linux 机选型）。

---

## 0. 一句话结论

**运行链路上只有两台电脑：树莓派（子站）+ Linux 机（主站）。**
**Windows 是开发机，不进运行链路。**
**那根 USB 转 485 会从 Windows 迁移到树莓派** —— 这是唯一一件"要换插"的事，也是下面最容易搞混的地方。

## 3. 电脑分工（本文最核心的一张表）

| 电脑 | 角色 | 装什么 | 接什么设备 | 进运行链路？ |
|---|---|---|---|---|
| **树莓派 2B** | 子站（值班室） | Raspberry Pi OS Lite 32 位；systemd 常驻；你的 104 子站程序 | **USB 转 485**（串起 485 总线）、网线、5V 电源 | ✅ 是（核心） |
| **Linux 机**（旧 PC） | 主站（调度中心） | Debian/Ubuntu Server LTS；开源 104 主站工具；PulseView | 网线、**逻辑分析仪** | ✅ 是（核心） |
| **Windows 11**（现在这台） | 开发机 | Python + pyserial（已装）、串口助手、SSH 客户端、IDE、git | **USB 转 485（仅开发期临时）**、可选逻辑分析仪 | ❌ 不进 |

### 关于那根 USB 转 485 的归属（最容易搞混的地方）

| 时期 | 插在哪 | 干什么 |
|---|---|---|
| **现在～Linux 机就位前** | **Windows** | 驱动已验证（COM3 / 沁恒官方驱动 3.9.2024.9）；先把变送器读通、把自检脚本跑熟 |
| **Linux 机就位后** | **树莓派** | 树莓派才是子站，它必须自己读设备。Windows 从此不再参与运行时链路 |

> 迁移动作就一句话：**把 USB 转 485 从 Windows 拔下来，插到树莓派的 USB 口上**，设备名从 `COM3` 变成 `/dev/ttyUSB0`（或 `/dev/serial/by-id/...`）。

## 4. 物理连接表

| # | 从 | 到 | 用什么线 | 参数 / 注意 |
|---|---|---|---|---|
| 1 | 变送器 `A` | USB 转 485 `A` | 单芯线（螺丝端子） | 接反 = 静默，不报错 |
| 2 | 变送器 `B` | USB 转 485 `B` | 同上 | — |
| 3 | 变送器 `电源负` | USB 转 485 `G` | 同上 | ⭐ **必须共地**，不共地表现为"时通时不通" |
| 4 | 变送器 `电源+ / 电源-` | 12V 电源 `+ / -` | 同上 | DC10-30V，12V 在区间内 |
| 5 | 继电器模块 `A / B` | 同一条 485 总线 `A / B` | 同上 | 与变送器并联在同一条总线上 |
| 6 | 继电器模块 `电源` | 12V 电源 `+ / -` | 同上 | DC9-16V，**绝不能给 24V** |
| 7 | 继电器模块 `DO1 COM / NO` | 继电器模块 `DI1` 两端 | 单芯线 | ⭐ **物理反馈闭环**：吸合→触点闭合→DI1 变位 |
| 8 | 继电器模块 `DI2` | 外部按钮/开关 | 单芯线 | 手动制造遥信变位，拍视频用 |
| 9 | 树莓派 `RJ45` | 路由器 | 网线 | Pi 2B **无 WiFi**，必须走网线 |
| 10 | Linux 机 `RJ45` | 路由器 | 网线 | 与树莓派同一网段 |
| 11 | 树莓派 `micro-USB` | 5V 2A 电源 | 原装线 | 不要用 12V |
| 12 | 逻辑分析仪 | Linux 机 `USB` | USB | PulseView 原生免驱（fx2lafw） |

### ⚠️ 为什么本阶段不做波形取证

USB 转 485 是**一体成型**的，TTL 侧（DI/RO/DE）封在黑色壳里，**探针没地方夹**；而 A/B 是差分信号，又**不能直接夹**（逻辑分析仪是 TTL 阈值，会读到垃圾）。要做波形必须额外加一块 MAX485 / SP3485，走 GPIO 串口把 DI/RO/DE 引出来。

**本阶段不做**：本协议跑在 TCP 上，物理层不是必需部分。逻辑分析仪留作后续备用，暂不采购。

## 5. 电从哪来

| 电源 | 供谁 | 规格 | 状态 |
|---|---|---|---|
| 12V 2A 适配器 | 变送器 + 继电器模块（并联，各走各的线） | DC12V 稳压，DC5.5×2.1 圆头 + 母转端子线 | **没有，要买 ¥15~25** |
| 5V 2A | 树莓派 | micro-USB | 有 |
| 220V 插排 | 上面两个适配器 | — | 有 |

**上电前必做**：万用表量空载电压（应 12.0~12.3V）、确认极性。
**禁止**：12V 接到 485 的 A/B；24V 接继电器模块（上限 16V）；用"12V 变压器"（可能是 AC 交流，会烧）。

## 6. 地址与端口清单

| 项 | Windows 开发期 | 树莓派运行期 |
|---|---|---|
| USB 转 485 设备名 | `COM3`（`USB\VID_1A86&PID_7523`） | `/dev/ttyUSB0` 或 `/dev/serial/by-id/...` |
| 变送器 | 从站 `0x01`，`4800 / 8 / N / 1` | 同 |
| 继电器模块 | 从站 `0x02`（目标），`4800/8N1`（目标） | 同 |
| 子站监听 | — | TCP **2404** |
| 主站连接目标 | — | `<树莓派IP>:2404` |

> ⭐ **Pi 上不要硬编码 `/dev/ttyUSB0`**：插拔顺序一变编号就变。用 `/dev/serial/by-id/` 或按 `VID:PID` 扫描。
> ⚠️ 而**两根一模一样的 CH340 都没有序列号**（实测你现有这根 `SER=` 为空），Linux 下 by-id 名字会**撞车**。所以第二条总线建议买**不同芯片**（CP2102 / FT232）。

## 9. 接错清单（这些错误看起来都像"协议 bug"）

| 现象 | 真因 | 会浪费你多久 |
|---|---|---|
| 完全收不到回包 | A/B 接反 / 没供电 / 从站号错 / 波特率错 / CRC 错 | 半天~1 天（五种现象一模一样，要靠排查顺序区分） |
| 时通时不通 | **没共地** / 杜邦公针在螺丝端子里松了 | 1~2 天（最阴险，会伪装成协议 bug） |
| 偶发 CRC 错、偶发超时 | 继电器吸合震动把线震松 / 总线干扰 | 1~2 天 |
| 读到全 0 | 寄存器地址配错（已实测：这台变送器读不存在的地址**返回全 0 而不报异常**） | 半天 |
| 值差 10 倍 / 100 倍 | 换算比例或字节序（温度必须按 `int16` 解析） | 半天 |
| 逻辑分析仪读到乱码 | 夹到 A/B 差分线上了 | 半小时 |
| Linux 下读错了设备 | 两个 CH340 无序列号，`ttyUSB` 顺序变了 | 半天 |

**排查顺序永远是**：① 物理层（接线/供电/共地）→ ② 参数层（波特率/数据位/校验/停止位/从站号，五个都要对）→ ③ 帧层（CRC/地址/功能码）→ ④ 时序层（静默间隔/超时）→ ⑤ 设备层（地址真的存在吗）。

---

## 10. 三条不能破的原则

1. **树莓派只干"子站"一件事**，不要在它上面同时跑主站、时序库、大屏。
2. **主站必须独立一台机器**，走真实网线——这是"网络"这一层存在的意义。
3. **Windows 不进运行链路**，它只是开发机和调试台。运行时的证据必须来自树莓派和 Linux 机。

### B. 继电器板关键参数（⚠️ 全部实测，不是手册推断）

| 项 | 结论 | 踩过的坑 |
|---|---|---|
| **编程口** | 板载 USB → CH340 → COM 口，**115.2 Kbps / 7-E-1** | ⚠️ **不是 FX 传统的 9600**；用 9600 连不上，报 `ES:01802007` |
| GX Works2 机型 | **FX3U(C)** | — |
| **RS485 端子** | ⚠️ **`485A0 / 485B0`** | ⚠️ 接 `485A1/B1` **完全无响应**（`D8120` 管的是 CH0 那一路） |
| RS485 参数 | **4800 / 8N1，从站地址 2** | — |
| **Y 输出（继电器）** | **线圈 `0x0500 + n`**，**FC01 读 / FC05 写** | ⚠️ **Y 是位软元件 → 用线圈**；FC03/FC06 写 `0x0500` 能写能回读但**继电器不动** |
| **X 输入（DI）** | **`0x0400 + n`**，FC02 读离散输入 / FC04 读输入寄存器 | FC04 仅 `0x0400` 有效，其它地址返回异常码 `02` |
| 梯形图（固定） | `LD M8002` / `MOV H0071 D8120` / `MOV K2 D8121` | `H0071` = 从站 + 4800 + 8N1 |

### C. 写-读-动作 闭环实测（2026-10-21）

```
FC01 读线圈 0x0500 → 02 01 01 00          Y0 = OFF
FC05 写线圈 0x0500 = ON  → 02 05 05 00 FF 00
                          ★ 继电器吸合（听到）
FC01 回读 0x0500   → 02 01 01 01          Y0 = ON（回读确认）
FC05 写线圈 0x0500 = OFF → 02 05 05 00 00 00
                          ★ 继电器松开（听到）
FC01 回读 0x0500   → 02 01 01 00          Y0 = OFF
```

⭐ 这是"遥控闭环"第一次在**真实硬件**上跑通；此前全部是内存执行器模拟。

### D. ⚠️ 已知边界：回读还不是完全独立

读 `0x0500` 是 **PLC 的 Y 映像**，与写入**同一条路径**——模块一坏两边一起错。

| 读哪里 | 含义 | 独立性 |
|---|---|---|
| `0x0500`（Y 映像） | PLC 认为自己输出了什么 | ⚠️ 与写入同路径 |
| `0x0400`（X 输入） | 外部 DI 的真实电平 | ✅ 真正独立 |

⭐ 真正的独立回读要**把继电器辅助触点接回 X0**。这一条正对应 `Actuator.readback()` 返回 `Optional[bool]` 的设计意图。
